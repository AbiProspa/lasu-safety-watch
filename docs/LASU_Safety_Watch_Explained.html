LASU Safety Watch

Design and Implementation of a Web-Based Crowdsourced Security and Incident Reporting System for Lagos State University (LASU)

1. What the system does

LASU Safety Watch lets students, staff and visitors report security threats and other campus problems from a phone or computer in about a minute. Each report has a description, a severity, a campus location with a map pin, and an optional photo. Users can report anonymously. Every report goes automatically to the LASU unit responsible for it (Campus Security, Works & Services, Medical Centre or Counselling). That unit verifies the report, assigns an officer, posts updates and marks it resolved. The reporter follows progress with a tracking code. Management gets a live dashboard with charts and hotspots.

Problem solved: Today, incidents at LASU are reported by walking to a security post, by phone or on WhatsApp groups. That leads to slow responses, lost records, no follow-up, and fear of reporting sensitive cases like cultism and harassment. This system puts every report in one secure place. Each report can be traced, the reporter's identity is protected, and responses can be measured.

3. Main features

  • Smart report form: 6 report types (Security, Harassment & GBV, Hostel, Facility, Environment & Flooding, Health & Emergency), each with sub-types, a severity level (Low to Critical), date and time, a LASU landmark plus a map pin ("use my location" or tap the map), and photo upload.
  • SOS panic button: a big red button with a 5-second countdown (which can be cancelled). It sends the user's GPS location to Campus Security without a login. Security staff see a flashing banner with a sound alert within 15 seconds.
  • Anonymous and confidential reporting: the user can tick "report anonymously". Harassment & GBV reports are always anonymous and never appear on the public map.
  • Tracking code: each report gets a code such as LSW-7K3P9Q and a public timeline (Received → Verified → In progress → Resolved).
  • Live incident map: an OpenStreetMap map of LASU Ojo campus with coloured pins by type, filters by type and date, and verified reports only.
  • Staff dashboard: KPIs (total, pending, active, resolved this month, average resolution time), a 14-day trend chart, category and status charts, top hotspot locations, and a "needs attention" list ordered by severity.
  • Case management: search and filters (status, category, severity, dates), change status and severity, assign an officer, add public or internal notes with a full audit trail, directions to the location, and CSV export for Excel.
  • Safety Center: one-tap call buttons for LASU and Lagos emergency lines (112, 767), plus safety tips.
  • Security: role-based access (each unit sees only its own reports), hashed passwords, CSRF protection, rate-limiting on login, reports and SOS (anti-spam), and validated uploads.

4. How it works

The system is a Laravel MVC web application. Routes send each request to a Controller. The Controller uses Models (User, Category, Report, ReportUpdate) to read and write the MySQL database, then returns a Blade view styled with Tailwind CSS. Maps use Leaflet with OpenStreetMap, charts use Chart.js, and interactive parts (SOS countdown, map picker, live alerts) use Alpine.js.

Report life-cycle: The user submits a report → it is validated and saved as Pending, with a tracking code → it appears on the responsible unit's dashboard → an officer verifies and assigns it (Verified / In progress) → each action is logged in report_updates → it is marked Resolved. The public map, tracking page and statistics update automatically.

Database tablePurpose
usersAccounts with role (admin, security, works, medical, counsellor, student)
categoriesReport types, the unit that handles each, colour, sub-types, confidential flag
reportsEach incident: code, type, severity, status, location, lat/lng, photo, reporter, assigned officer

5. Technologies used

PHP 8.3 and Laravel 12 (backend) · MySQL (database; SQLite for local testing) · Blade, Tailwind CSS 4 and Alpine.js (interface) · Leaflet and OpenStreetMap (maps) · Chart.js (charts) · Vite (asset build) · Docker, Render and Aiven MySQL (free deployment). Automated tests: 8 feature tests (php artisan test) covering reporting, anonymity, SOS, role permissions and the update workflow.

6. Running and deploying

On your PC: composer install → npm install → npm run build → php artisan migrate:fresh --seed → php artisan serve, then open http://127.0.0.1:8000. Admin login: admin@lasu.test / Admin@1234.

Online (free): the code is on GitHub; Render (free) builds the Dockerfile and runs the site, and Aiven (free) provides the MySQL database over an encrypted connection. On every start the app runs the migrations and creates the categories and staff accounts automatically (steps in DEPLOY-FREE.md).

Before going live: change all demo passwords, put the real LASU phone numbers and landmark coordinates in config/lsw.php, and set SEED_DEMO_REPORTS=false.
